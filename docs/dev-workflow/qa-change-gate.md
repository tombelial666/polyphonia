# QA change gate — commit and push

## Purpose

Сопровождать **любое** изменение кода и конфигурации так, чтобы перед коммитом и пушем было явно:

- что именно менялось (дифф);
- где это зафиксировано в `tasks/` (актуальное описание на момент попытки коммита/пуша);
- что все затронутые пути **учтены в `repo-index.yaml`** (или осознанно добавлены туда же коммитом);
- что индекс **согласован с тем, что уходит в dev** (ветка интеграции ниже).

## Confirmed

- Источник перечня путей репозитория: `repo-index.yaml` (`entries[].path`).
- Записи о работе ведутся в `tasks/*.md` (одна задача или несколько, но изменение рантайма/канона не «висят в воздухе» без обновлённого описания).
- Автоматическая проверка диффа: `python scripts/check_change_gate.py` (см. `--help`).
- Роль агента-ревьюера: `.cursor/agents/qa-change-gate-reviewer.md`, команда-шорткат: `.cursor/commands/qa-change-gate.md`.

## Assumption

- Ветка интеграции в dev по умолчанию сравнивается с `origin/develop`; если у команды другая — задаётся переменная окружения `PETS_CHANGE_GATE_BASE` или флаг `--base` у скрипта.

## Risk

- Скрипт не заменяет человеческий смысловой ревью: он ловит **отсутствие записи в индексе** и **отсутствие правок в tasks** по правилам по умолчанию, а не корректность музыки или UI.

## Deferred

- Жёсткий server-side pre-receive hook на Git-хостинге (здесь только локальный гейт и правила агента).

## Confirmed (CI)

- На push и pull request workflow `.github/workflows/ci.yml` запускает job `change-gate`: `python scripts/check_change_gate.py` с базой `origin/${{ github.base_ref }}` для PR и с `github.event.before` (или `HEAD~1` при первом пуше) для push.
- Job `e2e` зависит от успешного `change-gate` и гоняет Playwright-сценарии из `tests/e2e/offline_scales` на Ubuntu.

---

## Обязательный порядок перед `git commit` / `git push`

1. **Дифф** относительно базы интеграции в dev (по умолчанию `origin/develop`, иначе `PETS_CHANGE_GATE_BASE` / `--base`):
   - `git fetch`
   - `git diff --name-only <base>...HEAD` (или `...` для merge-base — скрипт использует merge-base с `<base>`).
2. **Задача в `tasks/`**  
   В активном файле задачи обновить блок **«Committed change record»** (шаблон: `tasks/_template.md`):
   - дата/краткий контекст попытки коммита или пуша;
   - список путей из диффа, которые относятся к продукту (не служебный мусор);
   - что проверено (ручной смоук, pytest, и т.д.).
3. **`repo-index.yaml`**  
   Любой новый или переименованный **существенный** путь из диффа должен появиться в `entries` (или осознанно относиться к уже объявленному префиксу вроде `docs/`, `assets/`).  
   После правок индекса в том же коммите (или в цепочке перед пушем в dev) индекс считается **актуальным для dev**.
4. **Автопроверка**  
   - перед коммитом (по индексу): `python scripts/check_change_gate.py --staged`  
   - перед пушем в dev (коммиты относительно базы): `python scripts/check_change_gate.py` (после `git fetch`)  
   При нарушении — исправить задачу или индекс, затем повторить.
5. **Агент** (рекомендуется для нестандартных диффов):  
   вызвать `qa-change-gate-reviewer` по инструкции в `.cursor/commands/qa-change-gate.md`.

## Исключения (скрипт)

- Только вывод в `build/`, `dist/`, `qa/results/`, `.pytest_cache/`, `__pycache__/` — не требуют задачи и не считаются «кодом продукта».
- Только зеркало `.claude/` и/или `CLAUDE.md` при отсутствии любых других материальных путей — запись в `tasks/` не требуется (см. логику «mirror-only material» в `scripts/check_change_gate.py`).

## Связь с «версией в dev»

**Confirmed:** однозначной автоматической связи «локальный коммит = то, что в dev» нет без CI.

**Практическое правило:** перед пушем в dev-ветку:

- `git fetch`;
- база сравнения = `origin/develop` (или значение `PETS_CHANGE_GATE_BASE`);
- индекс и задачи в коммите должны отражать **тот же набор путей**, который уйдёт в удалённый репозиторий после пуша.

Если dev — не `develop`, зафиксируйте это в `MANIFEST.md` или в командной wiki и выставьте `PETS_CHANGE_GATE_BASE` у всех разработчиков.
