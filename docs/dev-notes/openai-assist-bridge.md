# OpenAI bridge в Polyphonia Assist (pywebview)

## Confirmed

- Режим UI при запуске оболочки: **`POLYPHONIA_MODE=offline|assist`** пропускает стартовое окно; иначе (интерактивный запуск не из CI) показывается **графическое окно** `assets/polyphonia_startup.html`: кнопки **ONLINE** / **OFFLINE**; при ONLINE — поля **OpenAI API Key** и **Claude API Key** (сессионно в RAM; вызов API Anthropic в приложении пока не подключён). Подтверждение вызывает **`js_api.launch_main`** → переход на `index.html`. В **`offline`** панель Assist и GPT отключены в UI и блокируются в `js_api`; в **`assist`** доступны Assist и OpenAI при ключе. В открытом окне pywebview режим можно **переключить в «Настройки»** (радиокнопки + «Применить»): **`js_api.set_poly_mode`**, URL через `history.replaceState`; следующий **холодный** запуск снова из env/меню/старта.
- При открытии только `index.html` без query по умолчанию считается **`offline`**; для автотестов и разработки добавляйте `?poly_mode=assist` к URL или задавайте переменную окружения перед запуском лаунчера.
- Вызов идёт **только из Python** (`phrygian_app.py`): нет прямого `fetch` к OpenAI из `file://` (CORS и утечка ключа).
- Ключ: приоритет **`OPENAI_API_KEY`** в окружении процесса; опционально **сессионный ключ** в RAM через `js_api.set_openai_api_key` (не пишется в `localStorage`, не в git).
- Ответы ассистента остаются **reviewable** (системный промпт требует помечать догадки как Assumption, не подменять детерминированные данные грифа).
- Модель по умолчанию: **`gpt-4o-mini`** (переопределение: `OPENAI_MODEL`).
- Опционально строки панели Assist (после отображения в UI) дописываются в **`polyphonia_sessions/dialogs/assist-dialog-YYYY-MM-DD.md`** (UTC) через `js_api.append_assist_dialog_md`, если режим **`assist`** и в карточке «Настройки» включено сохранение в Markdown. Каталог в `.gitignore`; ключ в браузере: `polyphonia_dialog_md_enabled` (`1`/`0`, по умолчанию в assist — включено). В логе заголовки различают **ответ GPT** (`role: gpt` → «GPT (OpenAI)»), **ошибку GPT/API** (`gpt_error` → «GPT (ошибка)»), **системные сообщения UI** (`system` → «System (UI)») и **пользователя** (`user` → «User»).
- Сводка источника ключа (без раскрытия секрета): **`js_api.get_openai_connection`** → JSON `source`: `env` | `session` | `none`; UI обновляет строки в Assist и в «Настройки».
- Проверка ключа без полноценного чата: **`js_api.openai_ping`** — GET `https://api.openai.com/v1/models` с текущим ключом (короткое чтение ответа); ошибки сети/401 попадают в JSON для строки результата в настройках.

Подробнее про разделение GPT vs Claude и варианты развития: **`docs/dev-notes/assist-llm-login-ux.md`**.

## Практики в духе ведущих AI-поставщиков (упрощённо)

| Практика | Как сделано / план |
|----------|-------------------|
| Секреты не в репозитории | Только env / RAM-сессия; примеры без реальных ключей. |
| Минимизация данных | Чекбокс «прикладывать контекст» — явное согласие перед отправкой root/scale и т.д. |
| Таймаут и ошибки | HTTP ~90s; в UI возвращается `message` без утечки ключа. |
| Системные границы | Системный промпт: кратко, без выдачи истины грифа за приложение. |
| Наблюдаемость | Логировать только факт ошибки/кода ответа, не тело запроса с ключом. |
| Расширения | Позже: streaming, `OPENAI_BASE_URL` для совместимых прокси, жёсткий allowlist моделей. |

## Типы вопросов (разрешены по промпту)

- **Стиль / референс:** «в духе какой группы или гитариста», жанр, тембр, ритмическая подача — ответы **обзорные**, с пометкой Assumption; без дословного копирования чужих партий и без полных табов чужих произведений.
- **Творческий смысл:** назначение музыки в треке, роль гитары, настроение секции — кратко и без выдачи за единственную истину.
- **Связка с Polyphonia:** при включённом контексте модель видит root/scale/instrument из UI — не противоречь этим данным.

## Assumption

- Пользователь запускает `python phrygian_app.py` в доверенной среде; сессионный ключ в памяти процесса считается приемлемым компромиссом до OS keychain.

## Risk

- Любой скрипт на загруженной странице теоретически может вызвать `js_api`, если окно скомпрометировано — держать страницу локальной и не подмешивать внешний JS.

## Deferred / Open Question (coverage)

- **E2E покрытие** для `assets/polyphonia_startup.html` (кнопки ONLINE/OFFLINE/«Далее») теперь есть как Playwright‑сценарии с мок‑бриджем `window.pywebview.api.launch_main` (без реального pywebview).
- **Оконный менеджмент** (открепление Assist и тайлинг 50/50) покрыт юнитами Python, но без e2e на реальных окнах/координатах (зависит от окружения runner’а).
