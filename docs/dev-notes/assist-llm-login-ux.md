# Assist: «логин» в GPT и Claude — UX и варианты

## Confirmed (как сейчас)

- **Нет классического логина** внутри страницы: это локальное `file://` / pywebview-приложение, не SaaS-аккаунт Polyphonia.
- **OpenAI GPT** в окне приложения: ключ только у процесса Python — **`OPENAI_API_KEY`** в окружении (приоритет) или **сессионный ключ в RAM** через `set_openai_api_key` из панели Assist и дублирующие поля в **«Настройки → Подключения»**. Сводка источника и кнопка **«Проверить ключ»** (`openai_ping`) помогают понять состояние без догадок.
- **Claude (Anthropic)** в этом окне **не вызывается**: рабочий путь — **Claude Code CLI** в терминале (`claude login`, затем при желании `python scripts/claude_terminal.py` из корня репо). В настройках — краткое пояснение и копирование команды запуска.

## Assumption

- Пользователь ок с тем, что секреты держит в env или вводит один раз за сессию в доверенном процессе на своей машине.

## Risk

- Любой вызов `openai_ping` уходит в сеть с текущим ключом — использовать осознанно; ответы ошибок могут содержать фрагменты JSON от API (без намеренной утечки ключа из нашего кода).

## Deferred / Open Question

- Встроенный чат **Anthropic** в pywebview (отдельный `anthropic_chat` + ключ `ANTHROPIC_API_KEY`) — отдельный объём, политика ключей и UI.
- OS keychain / Windows Credential Manager для ключа вместо сессионного поля.
- Единый «мастер подключений» с OAuth провайдера (если появится hosted-режим).

## Risk (coverage)

- Текущее тест-покрытие сильнее по **Python API/контрактам** и слабее по **UI-потокам** (клики в сплэше, поведение окна/тайлинга). Это намеренно оставлено как следующий шаг: e2e сценарии под GUI дороже и требуют аккуратной инфраструктуры.

## Варианты улучшения (кратко)

| Вариант | Плюсы | Минусы |
|--------|--------|--------|
| **A — текущий** (env + RAM, сводка + ping, Claude снаружи) | Минимум кода, секрет не в localStorage, понятное разделение GPT/Claude | Два места ввода ключа (Assist + Настройки), нет единого «аккаунта» |
| **B** — только Настройки для ключа, Assist — одна ссылка «настроить» | Меньше дублирования | Ещё один клик до поля |
| **C** — keyring + один раз за установку | Удобнее для ежедневной работы | Сложность по ОС, тесты, отказоустойчивость |
| **D** — прокси-сервер на localhost с долгоживущей сессией | Можно абстрагировать провайдеров | Новый процесс/порт, модель угроз |

Рекомендация для PETS на ближайший горизонт: оставить **A**, при необходимости эволюции — **B** или **C** без смешения с «логином» внутри веб-страницы как у облачного продукта.
